Context. The project tests whether using YOLOv8's detection confidence to find uncertain detections, and refining their bounding-box prompt before it is passed to a frozen SAM 2, improves polyp segmentation over the YOLO-SAM2 baseline of Mansoori et al. [1]. Phase 2 prepared the data this needs: a primary dataset with a fixed train/validation/test split in YOLO format, an external dataset for the domain-shift test, a corrupted copy of the test split for the image-shift test, and a working environment in which the baseline pipeline runs on the prepared data. Every number in this report is read from the verification files written by the preprocessing scripts; every design choice is recorded with its alternatives and evidence in docs/decision_log.md (entries DL-01 to DL-29).

Kvasir-SEG is the dataset the baseline was trained and evaluated on, so it is the natural primary set. CVC-ClinicDB comes from a different hospital, a different endoscope and a different annotation team; it is used in its entirety as a held-out test set because the project's question is robustness to such shifts, and because its frames come from video sequences, so a random split would leak near-identical frames between train and test (DL-03). The baseline code (sajjad-sh33/YOLO_SAM2, commit d86e375) has no license; it was cloned for reading only, is cited, and none of it was copied into our repository (DL-16).

2. Data collection method

  • Kvasir-SEG was downloaded from the official URL on 2026-10-07: kvasir-seg.zip, 46,227,172 bytes, SHA-256 03b30e21d584e04fa…3478f7 (full hash in docs/data_report.md). The archive is kept next to the extracted files and the hash is re-checked after processing. On Google Colab the official link returned 0 bytes on 2026-10-09, so the notebook uses the dataset author's Kaggle copy (debeshjha1/kvasirseg); it reproduced exactly the same verification numbers, split and box counts (DL-26).
  • CVC-ClinicDB requires a login on the original site, so the Kaggle mirror used by the baseline authors (balraj98/cvcclinicdb, PNG version) was downloaded on 2026-10-09, once through the website and once through kagglehub on Colab; both gave 612 + 612 files with identical verification results. Kaggle re-packages archives on download, so the file-level record (counts, resolution, readability, box counts) is the provenance record instead of an archive hash (DL-24).
  • Raw data is never modified (DL-01). Downloads live in data/raw/, everything derived is written to data/processed/, and images are copied, never moved, unlike the baseline's own preprocessing script, which moves the original files. Datasets and weights are git-ignored and are not redistributed.

3. Preprocessing steps

All three preparation scripts (src/data/prepare_kvasir.py, prepare_clinicdb.py, make_corruptions.py) share one helper module and follow the same contract: verify every input file, stop before writing anything if a check fails, write the outputs, write a verification.json.

  1. Verification. Counts, one-to-one image/mask pairing, equal image and mask sizes (and, for Kvasir-SEG, agreement with the box file), full decoding of every image and mask, no empty mask after thresholding. Result: Kvasir-SEG 1,000 / 1,000 / 1,000, CVC-ClinicDB 612 / 612; 0 unreadable files and 0 empty masks in both (DL-11).
  2. Mask binarisation (DL-04). Kvasir-SEG masks are lossy RGB JPGs: every mask contains pixels that are close to but not exactly 0 or 255 (0.73% of all mask pixels), which the baseline reads as values like 0.98 that count as neither polyp nor background. No pixel lies between 11 and 244, so thresholding at 127 is unambiguous. All masks of both datasets are converted to single-channel PNGs with values 0 and 255 only.
  3. Specks (DL-05). After thresholding, Kvasir-SEG masks contain 143 isolated regions smaller than 0.05% of the image. They are kept in the masks (the ground truth is not edited) but ignored when boxes are derived, so YOLO is not trained on compression noise.
  4. Bounding boxes from masks (DL-06, DL-07). One box per connected polyp region (8-connectivity). The official Kvasir-SEG box file is not used as labels because it is wrong for 18 of 1,000 images (Section 4) and because CVC-ClinicDB has no box file; deriving boxes from masks gives both datasets the same definition. Boxes are (xmin, ymin, xmax, ymax) with exclusive maxima; on the 982 images where the official file agrees, it differs from ours by at most 1 px per side.
  5. Fixed, seeded split (DL-02). The paper's split cannot be reproduced (the baseline takes the first 800 files of an unsorted, unseeded glob). Image ids are sorted, shuffled once with seed 42 and cut 700 / 100 / 200; the lists are committed in splits/ and reused by every run, and an automated test fails if they change. The validation split exists so that the confidence threshold can be chosen without touching the test set. The split is random, not stratified: mean polyp area is 14.7% (train), 18.2% (val), 16.4% (test).
  6. YOLO format (DL-09, DL-15). Images are copied at their original resolution into images/<split>/, labels 0 x_center y_center width height (normalised) into labels/<split>/, with one class, polyp; configs/kvasir.yaml and configs/cvc_clinicdb.yaml describe the datasets to Ultralytics. No resizing or augmentation is done in preprocessing; CVC-ClinicDB goes entirely into a test split.
  7. Image-shift test set (DL-20). Three corruptions at three strengths are applied to the 200 Kvasir-SEG test images only: Gaussian blur (σ = 1, 2, 4 px), brightness/contrast (contrast ×0.8/×0.6/×0.4 around the image mean with a −20/−40/−60 shift) and Gaussian noise (σ = 10, 20, 40 on 0–255). Masks and labels are copied unchanged; noise is seeded per image so reruns are byte-identical; outputs are PNG so no extra JPEG artefacts are added. 9 settings × 200 images.
  8. Validation of the result. (a) 34 automated tests run on every push (GitHub Actions): helper functions, split files, and synthetic end-to-end runs of all three scripts. (b) An independent script re-checked every Kvasir-SEG output: 1,000 image copies byte-identical to the raw files, 1,000 masks with only 0/255 and equal to the thresholded originals, 1,000 well-formed labels that convert back to the mask boxes within 0.001 px. (c) An overlay check drew the mask outline and label box on 20 random test images per dataset: 20/20 correct on both. (d) A smoke test ran the baseline YOLO → SAM 2 pipeline on Colab (T4) on five prepared test images: it runs end to end, which confirms the data is ready for model implementation (Section 4).

  • A measurable domain shift exists. CVC-ClinicDB polyps are smaller (9.2% vs 15.4% of the frame), its frames are darker and lower-contrast, its boxes are wider than tall rather than roughly square, and its resolution is fixed and low. These are exactly the conditions under which a detector trained on Kvasir-SEG can become uncertain, which is what the proposed method targets. The statistics describe the datasets; they do not by themselves quantify the performance drop.
  • The official Kvasir-SEG box file is unreliable. Comparing it with mask-derived boxes: 982 images agree (extent IoU ≥ 0.985), but in 10 images the official box starts at pixel (0, 0) and covers 82–100% of the frame while the polyp covers 46–90% (IoU 0.46–0.90), and in 8 images it lists an extra box around a speck. Mean extent IoU over all 1,000 images is 0.987. Training YOLO on these boxes would teach it 10 badly wrong targets; deriving boxes from the masks avoids this.
  • Polyp size varies enormously. Kvasir-SEG polyp area ranges from under 1% to over 90% of the frame (median 11%). One test image's polyp fills 76% of the frame and its label box covers the whole image, which tells SAM 2 almost nothing about location; such near-full-frame boxes are a case the prompt refinement will have to handle.
  • The detector, not the segmenter, is the weak point. In the smoke test with the baseline's shipped weights, SAM 2 reached Dice 0.96–0.97 on the four images where YOLO found the polyp, and 0.00 on the fifth, where YOLO produced no box even at confidence 0.05. The baseline's evaluation code skips images without a detection, which would hide this miss (mean Dice 0.965 instead of 0.772 over the five images); our evaluation will count missed polyps as empty predictions (DL-18). These numbers come from weights whose training split is unknown and are not a reported result (DL-17).
  • Masks are not binary and contain noise. 0.73% of raw mask pixels are neither 0 nor 255, and 143 specks exist after thresholding. Without the cleaning in Section 3 both would silently distort Dice/IoU.

Environment. Data preparation runs locally on CPU (Python 3.12, numpy 2.5.3, Pillow 12.3.0, OpenCV 5.0.0.93, pinned in requirements.txt). Model work runs on Google Colab (T4): torch 2.11.0, ultralytics 8.4.174, SAM 2 at commit 2b90b9f (requirements-colab.txt); weights sam2_hiera_large.pt (898 MB) and yolov8m.pt are stored in Google Drive. The whole Phase 2 pipeline re-runs from a clean Colab session with F26-13.ipynb in about ten minutes.

Known limitations carried into Phase 3. The split is not stratified by polyp size; CVC-ClinicDB results will be cross-dataset and not comparable with the paper's in-domain numbers; the baseline's published code does not run as-is (notebook syntax in .py files, missing imports, indentation errors, a hard-coded confidence threshold of 0.5 and an evaluation that skips missed polyps), so the evaluation will be re-implemented; the paper and its code disagree on the YOLO model size and image size, so both will be recorded when we train.
